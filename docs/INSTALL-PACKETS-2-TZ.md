# Техническое задание
## Install Packets Script 2.0 — расширение установщика OpenWrt

### 1. Цель проекта

Доработать существующий универсальный установщик пакетов OpenWrt.

**Основной репозиторий:**  
https://github.com/TMN88/install_packets_script

**Основной файл:** `openwrt-toolkit.sh`

Не создавать новый репозиторий. Все доработки выполнить в существующем проекте, сохранив обратную совместимость и прежнюю команду установки.

Поддерживаемые системы:
- OpenWrt 24.10.x — opkg.
- OpenWrt 25.12.x — apk.
- Различные архитектуры процессоров с проверкой совместимости каждого компонента.

### 2. Новое меню установщика

Реализовать следующее меню:

```text
╔══════════════════════════════════════════╗
║          INSTALL PACKETS 2.0             ║
║       UNIVERSAL OPENWRT TOOLKIT          ║
╚══════════════════════════════════════════╝

Роутер: Netis N6 V2
OpenWrt: 25.12.x
Менеджер пакетов: apk
Архитектура: aarch64

Выберите пакеты для установки:

 1. Podkop
 2. Forkop
 3. AmneziaWG
 4. Zapret Manager
 5. Zapret2 Routerich
 6. AWG Test / VPN Failover
 7. Site Checker 2.0
 8. USB Modules
 9. YouTube Watchdog
10. SFTP Server
11. Tailscale (TS Mini / TS Routerich)
12. Темы LuCI (Footstrap / Argon / Aurora)
13. Терминал ttyd (LuCI)

 A. Установить все совместимые пакеты
 Q. Выход

Выбор: _
```

Оформление — фирменные неоновые ANSI-цвета: бирюзовый, фиолетовый, зелёный, жёлтый, красный.

Поддерживать выбор нескольких номеров через пробел или запятую.

Повторяющиеся номера игнорировать.

Отображать фактический статус каждого компонента.

### 3. YouTube Watchdog

**Репозиторий:**  
https://github.com/TMN88/youtube-watchdog

**Источник установщика:**  
https://raw.githubusercontent.com/TMN88/youtube-watchdog/main/install.sh

Требования:

1. Добавить отдельный пункт меню.
2. Проверять наличие службы `/etc/init.d/youtube-watchdog`, исполняемого файла и установленной версии.
3. При отсутствии запускать официальный установщик проекта.
4. При установленной рабочей версии пропускать переустановку.
5. Не менять настройки существующего Watchdog.
6. После установки проверять регистрацию службы и наличие интерфейса LuCI.
7. Не считать успехом только нулевой код дочернего скрипта — проверить конечное состояние.

Сохранять штатную логику проекта: проверка YouTube каждые 3 минуты по умолчанию, повторное подтверждение отказа, ограниченные попытки восстановления Zapret2.

Если Zapret2 отсутствует, не устанавливать его автоматически. Показать предупреждение о зависимости и позволить Watchdog выполнять собственную предусмотренную диагностику, если это поддерживается его установщиком.

### 4. SFTP Server

Добавить отдельный выбираемый пункт.

**Важно:** в текущем `openwrt-toolkit.sh` уже есть функция `install_sftp_server()`, но она вызывается безусловно. Исправить это.

Требования:

- Не устанавливать SFTP без выбора пользователя.
- Проверять `openssh-sftp-server`.
- Использовать `apk add` или `opkg install` в зависимости от системы.
- Проверять наличие исполняемого SFTP subsystem после установки.
- Проверять совместимость с действующим SSH-сервером (Dropbear или OpenSSH).
- При необходимости правильно интегрировать SFTP subsystem без замены основного SSH-сервера.
- Не изменять SSH-порт, существующие ключи, разрешения удалённого входа и firewall.
- Не отключать Dropbear.
- Не устанавливать полноценный OpenSSH daemon без подтверждённой технической необходимости.
- Не считать установленный пакет доказательством успешного SFTP-подключения.

При успешной установке вывести краткую информацию для подключения через Termius или WinSCP.

### 5. Site Checker 2.0

**Новый репозиторий:**  
https://github.com/TMN88/Site_Checker_2

**Источник установки:**  
https://raw.githubusercontent.com/TMN88/Site_Checker_2/main/install.sh

Полностью заменить старую установку Site Checker 1.x.

В текущей версии установщика используется закреплённая старая сборка из репозитория `TMN88/Site_Checker`. Удалить эту ссылку из активного механизма установки.

Требования:

1. Проверять установленную версию Site Checker.
2. Если версия 2.0 уже установлена и работает — пропускать.
3. Если установлена версия 1.x — сообщать о предстоящей миграции.
4. Учитывать, что официальный установщик версии 2.0 удаляет старую версию вместе с её конфигурацией.
5. Перед миграцией сохранять резервную копию настроек версии 1.x, если они существуют.
6. Использовать штатный установщик версии 2.0, не дублировать его логику.
7. Проверять наличие новой страницы LuCI, зарегистрированного RPC и файлов версии 2.0.
8. Не удалять конфигурацию уже установленной версии 2.0.

Установщик не должен считать остаточные файлы версии 1.x признаком установленной версии 2.0.

### 6. Tailscale — два варианта

**Репозиторий:**  
https://github.com/TMN88/TS_client_install

Реализовать вложенное меню:

```text
Установка Tailscale

1. TS Mini — официальный сервер Tailscale
2. TS Routerich — сервер rc.routerich.ru
0. Назад
```

**TS Mini**

Источник:

https://raw.githubusercontent.com/TMN88/TS_client_install/main/tailscale-router-mini.sh

**TS Routerich**

Источник:

https://raw.githubusercontent.com/TMN88/TS_client_install/main/tailscale-router-rr.sh

Требования:

- Запускать выбранный оригинальный установщик из репозитория.
- Не заменять его обычным `apk add tailscale`.
- Сохранять userspace networking и SOCKS5 0.0.0.0:1055.
- Не изменять DNS, netfilter, маршруты и существующую регистрацию без предусмотренного механизма подтверждения.
- Не передавать auth key через командную строку основного установщика.
- Для Routerich оставлять штатный скрытый запрос Device Auth Key.
- Не сохранять ключи в журналах.
- Не переключать уже подключённый TS между официальным сервером и Routerich автоматически.
- Если TS уже установлен, различать установленный пакет, состояние службы, регистрацию и сервер управления.
- Если обнаружена существующая регистрация в другой сети — предупредить и передать управление штатной логике дочернего установщика.

После выполнения проверять успешность установщика и его итоговую диагностику.

**Особенно важно:** обычный SSH-доступ к Tailscale IP не гарантируется самим фактом работы userspace networking. Не выводить утверждение об успешном удалённом SSH без реальной проверки.

### 9. Общие правила установки

Для каждого компонента выполнять одинаковую последовательность:

1. Проверка совместимости.
2. Проверка установленного состояния и версии.
3. Проверка необходимых зависимостей.
4. Установка или пропуск.
5. Проверка результата.
6. Запись результата в итоговую таблицу.

Статусы:

- УСПЕШНО
- УСТАНОВЛЕН РАНЕЕ
- ОШИБКА
- НЕ ПОДДЕРЖИВАЕТСЯ
- ТРЕБУЕТ НАСТРОЙКИ
- ПРОПУЩЕНО

Ошибка одного компонента не должна останавливать установку следующих.

Не считать ошибку установки `ip-full` причиной автоматического отказа от установки Zapret Manager. Сохранить существующую логику: предупреждение и попытка дальнейшей установки.

Не устанавливать одновременно Podkop и Forkop, если обнаружен конфликт. Сохранять ограничения Zapret / Zapret2 и Routerich.

Не добавлять автоматическую установку классического Zapret2 вместо Routerich.

### 10. Правила команды «Установить все»

Не выполнять слепую установку всех пунктов.

При выборе `A`:

- Устанавливать совместимые независимые компоненты.
- Не устанавливать одновременно конфликтующие реализации обхода блокировок.
- Не переключать существующую Tailscale-сеть.
- Не выбирать произвольную тему оформления.
- Не запускать вложенные меню без осмысленного выбора пользователя.
- Не устанавливать принудительно SFTP и ttyd, если они исключены из политики автоматической установки.

Для компонентов, которым нужен выбор варианта, оставить отдельный ручной выбор либо спросить вариант в явно обозначенном подменю.

Вывести список действий до начала выполнения без дополнительного глобального подтверждения.

### 11. Локализация и перезагрузка

Автоматическую установку русского языка LuCI сохранить.

Не делать её отдельным пунктом выбора.

Если локализация уже установлена — пропустить.

Общее подтверждение установки не требуется.

Предлагать перезагрузку только если в ходе текущего запуска успешно установлен AmneziaWG и это требуется для применения его компонентов.

Самостоятельно перезагрузку не выполнять.

### 12. Вывод в SSH

Обязательно соблюдать стандарт оформления терминальных скриптов проекта.

Использовать яркие ANSI-цвета.

Каждый полный запуск должен иметь явно выделенные границы:

- `НАЧАЛО`
- `КОНЕЦ`

Обе границы визуально выделить неоновым оформлением.

Вывод по-русски, компактный, без ненужных повторов.

Поддержать `NO_COLOR=1`.

В конце отображать итог:

║          ИТОГИ УСТАНОВКИ               ║
╚════════════════════════════════════════╝

YouTube Watchdog    УСПЕШНО
SFTP Server         УСПЕШНО

Все статусы должны соответствовать фактическим проверкам, а не только возврату кода 0 из установщика.

### 13. Безопасность

- Не выполнять неизвестный код без проверки источника.
- Загружать shell-файлы во временный каталог.
- Проверять непустое содержимое и shell-синтаксис.
- Использовать опубликованные контрольные суммы, когда они доступны.
- Удалять временные установочные файлы.
- Не выводить секретные ключи.
- Не менять SSH, firewall, DNS или маршруты без необходимости.
- Не ломать уже установленные приложения.
- Сохранять настройки при повторном запуске.
- Исключить случайное удаление других пакетов.
- Исключить случайный запуск перезагрузки.
- По возможности тестировать и закреплять известную рабочую версию внешнего установщика.

### 14. Тестирование

Провести проверки:

1. OpenWrt 24.10 / opkg.
2. OpenWrt 25.12 / apk.
3. Пакет отсутствует.
4. Пакет уже установлен.
5. Предыдущая версия установлена.
6. Несовместимая архитектура.
7. Недоступный GitHub.

12. Отказ от выбора Tailscale или темы.
13. Миграция Site Checker 1.x → 2.0.
14. Работа Watchdog при наличии и отсутствии Zapret2.
15. Установка SFTP без изменения действующего SSH.
16. Сохранение текущей регистрации Tailscale.
17. Корректный итоговый отчёт при частичных ошибках.

Использовать ShellCheck и `sh -n`, а также изолированные тесты с имитацией `apk`, `opkg` и системных служб.

Если реальное аппаратное тестирование не проводилось, прямо указать это в результатах.
